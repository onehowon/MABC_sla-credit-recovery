# SLA Recovery Agent v1 PRD

**기능명:** SLA 크레딧 청구 준비 · **데모:** https://mabc-sla-credit-recovery.vercel.app

## 1. 배경/문제

Compute Engine 장애 뒤 사용자는 SLA 위반 여부, 증빙, 기한, Support에 보낼 초안을 여러 화면과 문서에서 다시 정리해야 한다. 이 과정에서 월 경계·중복 구간·반올림을 잘못 해석하면 청구 기회를 놓치거나 사실과 다른 자료를 제출할 수 있다. 이 도구는 사람의 청구 검토를 위한 결정론적 정리 과정을 한 흐름으로 제공한다.

## 2. 사용자

단일 GCE 인스턴스 장애를 겪은 개발자·SRE·클라우드 운영 담당자. SLA 정책을 매번 계산하지 않고, 장애 기록을 Support 검토용 자료로 정리하려는 사용자다.

## 3. 목표와 성공 기준

- 장애 기록 입력 뒤 **3분 이내** Support에 붙여넣을 수 있는 사람 검토용 초안을 만든다.
- 각 결과 상태에서 제목·결론·근거 숫자·다음 행동을 모두 보여줘 막다른 화면을 만들지 않는다.
- 월 경계 clip, union, 제외, 반올림이 발생하면 변형 사실과 원본/계산값 차이를 사용자에게 고지한다.

### 표시 자릿수 규칙

표시 MUP은 항상 `toFixed(2)`로 **소수점 둘째 자리까지 고정**한다(예: `99.80%`, `99.88%`, `99.90%`). trailing zero를 제거하지 않는다. SLA breach/tier 판정은 표시값이 아닌 반올림 전 unrounded MUP으로 수행한다. 따라서 44분 사례는 `99.90%`로 표시하되 실제값 `99.9014%`가 99.90% 이상이므로 미위반임을 함께 설명한다.

표시값이 임계선 `99.90%`와 같아지는 경우에는 반올림 전 실제값과 판정 이유를 인라인으로 강제한다. 안전한 방향은 `99.90% (실제 99.9014% — 반올림 전 기준 99.90% 이상이라 미위반)`, 위험한 방향은 `99.90% (실제 99.8996% — 반올림 전 기준 99.90% 미만이라 위반)`처럼 표시한다.

## 4. 범위 In / Out

**In:** GCE Single Instance, Premium Network Tier, E2, standard provisioning, external connectivity loss, 인스턴스·NIC·network tier·폐쇄 월 각각 하나. RFC3339→UTC 정규화, 월 경계 clip/split, 중복 구간 union, 분 단위 정수 계산, unrounded MUP 기반 tier 판정, claim draft 생성을 포함한다.

**Out:** Spot/Preemptible, Standard Tier, 여러 VM/NIC/tier 혼합의 강제 계산, 실제 클레임 자동 제출, provider 승인 보장, 법률 자문.

**v1에서 제외:** verified exclusion(검증된 제외 구간) 차감. 계산기에는 구현돼 있으나 사용자가 제외 구간을 입력·검증하는 화면 흐름이 없으므로 v1 기능 범위에서 뺀다.

## 5. 비목표

v1은 **목업 전용**이다. 화면에는 항상 `데모 모드 · 목업 인스턴스 기반 계산`을 표시하고, 지원 범위가 검증된 목업 인스턴스만 선택한다. 실시간 GCP discovery·evidence 조회, OAuth·서비스 계정 키, 실제 클레임 자동 제출은 포함하지 않는다. 로그가 Google 장애 또는 100% 다운을 확정한다고 주장하지 않으며, billing 미검증 금액은 잠정값일 뿐 승인 금액이 아니다.

## 6. 화면 상태 매트릭스

결과 화면은 “C/E 같은 독립 화면”을 늘리는 방식이 아니라, **판정 축이 골격을 만들고, 청구 준비 축이 제출 가능성을 설명하며, 변형 축이 누적 배너를 얹는 방식**으로 구성한다. 모든 조합은 제목·결론 한 문장·근거 숫자·다음 행동의 4칸을 채운다.

### 6-1. 판정 축 — 화면 골격

| 판정 상태 | 발생 조건 | ① 제목 | ② 결론 한 문장 | ③ 근거 숫자 | ④ 다음 행동 | 배포본 실측 상태 |
|---|---|---|---|---|---|---|
| A. 위반 | unrounded MUP < 99.90% | 이번 달 복구 기회 | 크레딧 청구 가능성을 확인했습니다 | 55분, raw 99.8768%, 표시 99.88%, tier | 청구 준비 상태에 따라 초안 검토/증빙 보완 | **구현됨** |
| B. 미위반 | unrounded MUP ≥ 99.90% | 장애 분석 결과 | 현재 입력으로는 청구 대상이 아닙니다 | 44분, raw 99.9014%, 표시 99.90% | 계산 근거 보관/입력 수정 | **구현됨** |
| D. 계산 불가 | 대상 월에 계산할 구간이 없음 | 대상 월 확인이 필요해요 | 이번 달에 계산할 구간이 없어 SLA 판정을 보류 | 입력 60분 → 이번 달 0분(대상 월 밖 제외), 집계 0분 | 입력 수정 | **구현됨** |
| F. 범위 밖 | Standard/Spot/Preemptible/복수 VM·NIC 등 v1 범위 밖 | 범위 확인 필요 | v1 지원 범위 밖이라 자동 판정을 하지 않습니다 | 범위 밖 사유(예: Standard tier, Spot, N2) | 입력 수정하기 | **구현됨** |

### 6-2. 청구 준비 축 — 판정과 직교

| Claim Readiness | 발생 조건 | 화면 의미 | 다음 행동 |
|---|---|---|---|
| READY_FOR_HUMAN_CLAIM_REVIEW | 위반 + 최소 evidence 충족 + deadline blocker 없음 | 계산은 위반이고 사람이 청구 초안을 검토할 수 있음 | 풀 Claim Pack 검토·복사·다운로드 |
| NEEDS_REVIEW | 위반이지만 evidence 부족 또는 deadline/billing 등 확인 필요 | breach 판정과 별개로 제출 준비가 미완 | 증빙/미해결 항목 보완 후 초안 검토 |
| NOT_APPLICABLE | 미위반 | credit tier·deadline/notice gate 없음 | 계산 근거 보관 또는 입력 수정 |

`D. 계산 불가`는 위 Claim Readiness 축에 넣지 않는다. D는 계산할 월 구간 자체가 없는 입력 상태이고, `NEEDS_REVIEW`는 계산은 완료됐지만 제출 준비가 미완인 상태다.

### 6-3. 변형 축 — 결과 상단 누적 배너

| 변형 상태 | 발생 조건 | 배너에 필수로 보일 3튜플 (원본값 → 변형값, 사유) | 조합 예시 | 배포본 실측 상태 |
|---|---|---|---|---|
| T0. 없음 | 입력 구간이 대상 월 안에 있고 중복·제외 없음 | 렌더하지 않음 | A + T0, B + T0 | 해당 없음 |
| T1. 월 경계 clip/split | 한 구간이 대상 월 경계를 넘음 | `입력 120분 → 이번 달 60분, 다음 달 60분 분할, 월 경계` | A + T1 또는 B + T1 | **구현됨** — 결과 상단 배너에 `원본 120분 → 이번 달 60분 / 대상 월 밖 60분 (월 경계 clip/split)` 노출 |
| T2. 월 밖 제외 | 한 구간이 대상 월과 전혀 겹치지 않음 | `입력 60분 → 이번 달 0분, 대상 월 밖 제외` | D + T2, A/B + T2 | **구현됨** — `원본 60분 → 이번 달 0분 (대상 월 밖 제외)` 노출 |
| T3. union 중복 제거 | 둘 이상의 구간이 겹침 | `원본 2개 구간/총 N분 → union 후 1개/M분, 중복 제거` | A/B + T3, T1 + T3 | **구현됨** — `원본 대상 월 안 입력 120분 → union 후 90분 (겹치는 장애 구간 중복 제거)` 노출 |

따라서 과거의 C(부분 clip), E(유효+월 밖 혼합)는 판정 축의 독립 상태가 아니라 각각 `A 또는 B + T1`, `A 또는 B + T1/T2` 조합이다. 이 구조는 **미위반 + clip**도 자연스럽게 포함한다. C·D·E의 공통 결함은 모두 **변형 고지 누락**이며, 하나의 배너 계약으로 해결한다.

### 6-4. 산출물 명세와 상태별 정책

| 상태 | 전체 복사 / Markdown 다운로드 정책 |
|---|---|
| A + READY | 풀 팩: §1~§5와 Support 초안 |
| A + NEEDS_REVIEW | 검토용 풀 팩: §1~§5와 미해결/증빙 보완 경고 |
| B (NOT_APPLICABLE) | 계산 근거 축약본: §1 장애·리소스, §2 계산, §4 미해결/재분석 안내. 청구 요청문은 제외 |
| D (계산 불가) | 계산 근거 축약본: §1 원본 입력, §2 변형/대상 월 불일치, §4 입력 수정 안내. 청구 요청문은 제외 |
| F (범위 밖) | 산출물 없음. 범위 밖 사유와 사람 검토 안내만 표시 |

**전체 복사:** 아래 순서의 평문 Markdown을 클립보드에 복사한다.

1. `# SLA Credit Claim Pack` 및 분석 대상 월/판정 요약
2. `## 1. 장애와 대상 리소스` — **원본** outage timestamp, 프로젝트·인스턴스·리전·NIC·tier·시리즈·provisioning
3. `## 2. 가동률 계산 내역` — 원본/변형/사유 배너, 월 총 분, union·제외·적격 분, raw·표시 MUP, tier
4. `## 3. 증빙 자료 확인` — 원본 로그/링크와 충분성 상태
5. `## 4. 제출 전 확인할 것` — deadline, billing basis, cap 등 NEEDS_REVIEW 항목
6. `## 5. Support 문의 초안` — 사람이 검토할 요청문
7. 실제 제출 전 사람 검토 필요 안내

**Markdown 다운로드:** 파일명은 `sla-claim-pack-YYYY-MM.md`이며, 위와 동일한 1~7 구조를 UTF-8 Markdown으로 저장한다. 현재 선택적으로 존재하는 내용이 아니라 이 순서와 구조가 산출물 계약이다.

### 6-5. 증거 상태 판정 기준

| 상태 | 판정 기준 | 화면/초안 표현 |
|---|---|---|
| SUFFICIENT | **입력 자료 텍스트에** 대상 인스턴스 식별값, 장애 시작·종료 시각, external connectivity loss 표현이 **모두 포함된 경우** | `입력 자료 기준 최소 요건 충족` — 자료의 원본성·Google 책임·최종 승인 여부는 검증하지 않는다 |
| INSUFFICIENT | 위 세 요소(인스턴스 식별값, 양 끝 시각, 장애 유형 표현) 중 하나 이상이 입력 자료에 없음 | `증빙 보완 필요` 및 누락 요소를 §3에 열거 |
| UNDETERMINED | 대상 월 구간이 없거나, 목업의 짧은 메모처럼 증거 범위를 판정할 수 없음 | `증거 상태 확인 불가` — 제출하지 말고 원본 자료를 확인 |

이 판정은 **입력된 텍스트에 필요한 요소가 들어 있는지를 확인하는 수준**이다. 해당 로그가 실제로 발생한 것인지, 그 장애가 Google 인프라 책임인지, SLA가 정의하는 Downtime에 해당하는지는 **검증하지 않는다.** 그 판단은 Google의 공식 검토에 속하며, 이 도구는 사람이 검토할 자료를 정리하는 데까지만 관여한다.

## 7. 엣지 케이스

- 대상 월 밖 구간은 0분·100%·증빙 충분으로 오인시키지 않고 D 상태로 보류한다.
- 월을 걸치는 구간은 계산상 clip/split하되, 원본 장애 시각은 제출용 사실로 보존하고 계산용 clip 시각은 별도 병기한다.
- 유효 구간과 월 밖 구간이 섞여도 진행을 막지 않으며, 제외 사실을 결과에 남긴다.
- 종료=시작, 종료<시작, 한쪽만 빈 입력, 둘 다 빈 행을 구분해 안내한다. 둘 다 빈 행은 무시한다.
- 중복 구간은 union 후 계산하며, 원본 구간과 union 결과의 차이를 고지한다.

## 8. 미해결 (NEEDS_REVIEW)

deadline 기준점(SLA 본문과 공식 제출 폼의 표현 차이), 인정되는 증거 종류·범위, credit cap 수치는 임의로 확정하지 않는다. 해당 값은 결과와 초안에서 **NEEDS_REVIEW / 사람 확인 필요**로 남기며, 실제 제출·승인·지급을 보장하지 않는다.

산출물 §4에는 다음 문장을 고정으로 렌더한다.

- **청구 기한:** `SLA 본문의 eligible 시점 기준과 공식 제출 폼의 월 종료 기준 표현이 다릅니다. 담당자가 적용 기준과 마감일을 확인해야 합니다.`
- **증거 범위:** `현재 자료가 인스턴스·장애 시작/종료·외부 연결 손실을 모두 연결하는지 담당자가 원본 로그 또는 지원 케이스로 확인해야 합니다.`
- **credit cap / billing basis:** `예상 금액과 최대 credit cap은 청구 대상 billing basis 확인 전 잠정값입니다. Billing 담당자 또는 Google 공식 절차에서 확인해야 합니다.`

산출물 §2의 tier 근거는 항상 raw MUP 인과를 포함한다. 예: `raw 99.8992% < 99.90% 이므로 10% tier (표시값 99.90%)`.
